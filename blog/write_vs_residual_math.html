Write-time vs residual-time sensed steering: a two-block derivation

The identities below and the two-block unrolling were checked numerically (float64, error < 1e-13). The numbers in section 4 come from the saved v and s of the two residual-site edits.

Two blocks is also exactly our real setting: the Astra-regime arms edit two layers, 15 and 19. Block 1 below is layer 15; block 2 is layer 19, and the writes of layers 16–18 fold into a~2 (they are part of the stream, never sensed by a write-time edit).

0. Setup

Two pre-norm blocks. The residual stream starts at the embedding h0. Each block writes an attention term and an MLP term:

aℓ=Attnℓ(hℓ−1),mℓ=MLPℓ(hℓ−1+aℓ),wℓ=aℓ+mℓ.

Unedited:

h1=h0+w1,h2=h0+w1+w2.

The edit operator at block ℓ (steering vector vℓ, sensing vector sℓ):

Pℓ=I−vℓsℓ⊤,Pℓy=y−vℓ(sℓ·y).
  • Write-time (our weight edit, Astra's edit): apply Pℓ to the MLP write mℓ only.
    • This is exactly Wdown←PℓWdown.
  • Residual-time (our resid_* arms): apply Pℓ to the block output hℓ, i.e. to everything in the stream.

A tilde marks quantities in the edited run: a~ℓ,m~ℓ are what block ℓ writes when it reads the edited stream. All nonlinearity (attention, RMSNorm, MLP) hides inside the tildes and is present in both schemes, so the bookkeeping is exact, not a linearization.

1. Write-time: a flat sum

h~1=h0+a~1+m~1−v1(s1·m~1)
h~2=h0+w~1+w~2−v1(s1·m~1)−v2(s2·m~2)(1)
  • Sensed: each edit reads only its own block's MLP write, sℓ·m~ℓ.
  • Never sensed: the embedding, attention writes, and the other block's write.
  • Each writer is touched once by one fixed linear map, so this is a weight edit.

2. Residual-time: a product, with a cross term

h~1=P1(h0+w~1)
h~2=P2(h~1+w~2)=P2P1(h0+w~1)+P2w~2(2)

Expanding the product:

P2P1=I−v1s1⊤−v2s2⊤+(s2·v1)v2s1⊤.

Written out, with x=h0+w~1 (the stream after block 1, before its edit):

h~2=x+w~2−v1(s1·x)−v2(s2·x+s2·w~2)+v2(s2·v1)(s1·x)(3)

Read term by term, block 2's edit senses three things:

s2·(h~1+w~2)=s2·w~2current write+s2·xprevious stream, raw−(s2·v1)(s1·x)block 1's correction, re-sensed
  • Block 1 senses the embedding plus its own attention and MLP writes.
  • Block 2 senses all of that again, plus its own write, and the correction block 1 just made. The last term is the recursion: with more blocks, each edit re-senses every earlier correction.
  • Compare (1): write-time has no s·x term and no cross term.

3. Same (v,s) at both blocks

Let β=s·v, the effective gain (for s=αv with unit v, β=α). Since (vs⊤)2=βvs⊤:

P2=I−(2−β)vs⊤.

The total change at the top of the two-block stack:

write-time:Δ=−v[s·m~1+s·m~2](4)
residual-time:Δ=−v[(2−β)(s·h0+s·w~1)+s·w~2](5)

As a scalar recursion on the sensed coordinate σℓ=s·h~ℓ:

write-time:σ2=σ0+s·a~1+s·a~2+(1−β)(s·m~1+s·m~2)(6)
residual-time:σ2=(1−β)2(σ0+s·w~1)+(1−β)s·w~2(7)
  • Write-time: each MLP write's sensed coordinate is multiplied by (1−β) once. Everything else passes through.
  • Residual-time: the latest write gets (1−β); everything older gets (1−β)2. With L edited blocks the oldest content gets (1−β)L.
β=s·v weight on older content, 2−β factor on older σ, (1−β)2 meaning
1 (s=v, projection) 1 0 Every writer sensed exactly once; P2=P.
0<β<1 between 1 and 2 between 0 and 1 Older content removed more than the latest write; contracting.
1<β<2 between 0 and 1 between 0 and 1 σ flips sign at each edit but shrinks.
β>2 negative >1 Unstable: each edit flips and amplifies. β=4: older content ×9.

4. Consequences

  1. When residual-time is a weight edit.
    • β=1 at every layer: P2=P, so residual-time equals editing every writer once (embedding, every attention WO, every MLP Wdown). This is Arditi et al.'s directional ablation ⇔ weight orthogonalization (their App. E).
    • Otherwise: block 1's write reaches block 2's input as P1w~1 but reaches the output as P2P1w~1. One fixed matrix per writer can't give both, so it is not a weight edit.
    • Astra's (and our) edit is the write-time branch.
  2. Same α is not the same strength. Residual-time also senses the embedding, the attention writes and all the accumulated stream. Most of the stream's norm sits there: in Qwen3 block 18 (an earlier round of experiments) the loop-direction projection was 182 for h vs 29 for x.
  3. Our residual arms, exactly (layers 15 and 19, different v,s per layer, so (3) with the cross term):
    • resid_sv_n32_a4: sℓ=4vℓ, so β=4, 1−β=−3; cross term s19·v15=3.41 (v15·v19=0.85).
      • Stream content before layer 15 along v15 comes out with norm 7.8× its input (coordinate +5.7 on v15, +7.7 on v19): flipped once to −3, then flipped and amplified again by layer 19.
      • The write-time twin maps layer 15's MLP write along v15 to −3× and leaves the rest of the stream alone.
      • Prediction: resid_sv is far stronger than its write-time twin and likely harmful. Measured in the Astra regime (1,152 problems): 2.9% accuracy and a 96.4% loop rate, against 60.7% and 27.2% for the same edit at the write.
    • resid_ul_n32_b0.1: learned s, mostly not along v (cos(s,v)≈0.15, ‖s‖≈2.1), so β=0.34 (layer 15) and 0.29 (layer 19); cross term 0.17.
      • Content before layer 15 along v15 comes out at 0.57×; write-time leaves that content at 1× and maps only layer 15's own MLP write to 0.66×. Stable, no flips, only somewhat stronger.
      • Prediction: resid_ul behaves close to its write-time twin, although it reads s·h~, a quantity s was never trained on. Measured: 61.6% accuracy and a 4.6% loop rate, against 61.6% and 6.5% for the same edit at the write.
  4. Astra's masked edit fits section 1 with a different sensing input: block ℓ reads αu·Wdown[:,S]zS (z the MLP hidden activation, S the top-64 neurons), a part of the MLP write. Still flat, still a weight edit.

5. What this suggests measuring (not run)

  • Sensed coordinates first. On the unedited dev rollouts (teacher-forced), log per token s·m~ℓ (write) and s·h~ℓ (residual) at layers 15 and 19, and the resulting ‖Δ‖. One forward pass per arm shows whether an arm is in the flip-and-amplify regime.
  • Then output change. KL(base‖edit) on loop vs productive tokens, matching the two sites on productive-token KL before comparing loop-token KL.
